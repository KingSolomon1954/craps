Detailed Description

One YAML file, held as a document made of named sections.

Owns the path and the root YAML node of a single file. It knows how to read and write the file and nothing about what is in the sections. A file is a map of top-level sections, for example a player file:

Player: # Craps::Player::toYAML(); read by Craps::Player::fromYAML()
playerId: ...
Bank: ...
Prefs: # PlayerPrefs::toYAML(); optional
LastFills: [...]

and a table file, which has just the one:

Table: # Craps::CrapsTable::toYAML()
tableId: ...

The model classes only ever see their own section. The managers (PlayerManager, TableManager) own the YamlFile, decide which sections a file has, and decide when to read and write it.

  • load() reads the file and keeps the whole document. The one section the caller names is required, anything else is optional.
  • setSection() replaces a section wholesale. Any other top-level section found in the file is kept and written back.
  • save() writes the document to a temporary file next to the real one and renames it over the real one, so a failed or interrupted write can never leave a half-written file behind.
  • getSection() returns a copy, since YAML::Node has reference semantics. A missing section comes back as a null node.

All failures are std::runtime_error with the file's path in the message.
