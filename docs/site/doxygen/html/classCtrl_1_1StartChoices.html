Detailed Description

Decides which table and players the game starts with.

Three sources can speak, and they have a fixed order of authority:

  • The user's config.yaml: what the user wants, always.
  • state.yaml: what the last game left, used for whatever config.yaml did not say.
  • The packaged defaults in sys-config.yaml: used on a fresh install, when neither of the others has an opinion.

Each setting is decided independently:

  • Table: startWithTable, else last table, else default table.
  • User player: startWithUserPlayer, else last user player, else default user player.
  • Buddies: if startWithBuddyPlayers is false there are none. Otherwise startWithTheseBuddyPlayers, else the last buddies, else the default buddies. A state file that exists remembers an empty list faithfully, it is not replaced by the defaults.

A name that is not a file in the user's tables or players directory is skipped with a warning in the log, and the next source is tried (for buddies, the one buddy is dropped). The user player is never also a buddy and there are at most UserState::MaxBuddies buddies. The game must always be able to start, so the worst a wrong name in a hand-edited config.yaml can do is cost the user what they asked for.

apply() puts the answer under the keys the rest of the game reads: table.startTable, table.userIsPlayer and table.startPlayers[0..5], the user player first.
