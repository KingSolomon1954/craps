Detailed Description

Management across multiple Craps Tables.

Table files

Craps::CrapsTable knows nothing about files. It only converts itself to and from YAML. TableManager owns the rest, the same way PlayerManager does for players:

  • loadCrapsTable() reads the table's file once, keeps it as a YamlFile and builds the CrapsTable from its "Table" section.
  • shutdown() shuts the current table down, which in turn shuts down all of its players and merges the session into their stats and the table's. It then takes a fresh snapshot of the table and writes its file. Failures are logged with LOG_ERROR. Call it once at quit, and before PlayerManager::shutdown(), which saves the players afterward.
  • switchCrapsTable() moves the user player, and the buddies who follow, to another table. See below.
Switching tables

switchCrapsTable() loads the new table first, so a table file that cannot be read leaves everything as it was. After that it does not fail:

  • Betting must be open. Every seated player ends the session at the old table: bets come down, money returns to the player, stats merge.
  • The old table is closed, which records its session, and saved.
  • The new table becomes the active one (Gbl::pTable) and the user player, then each buddy who follows, joins it, in the seating order they had. The user is the shooter. Buddies who do not follow are saved and are out of the game until someone seats them.
  • The old table object is kept in retired_ rather than deleted. Another thread may be reading the table as the switch happens, and a retired table is a closed, empty one, which is safe to read.
  • Undo history is cleared, and AutoOdds forgets the bets it had handled.
  • The players' files are saved.

The caller, EventHandler, answers the View and sends the events that tell it the table changed.
